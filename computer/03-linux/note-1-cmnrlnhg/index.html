    进程的退出状态

    退出状态用于指示程序的错误情况，一些特殊的值具有特殊的含义，具体的值与shell和操作系统有关

    在Linux中

    0代表正常

    非0代表异常

    bash -c "exit 42"
echo $?
42

    Echo \$?打印上一个退出的程序的退出状态

    1通常代表最普通的错误

    2代表误用了shell内置的命令，例如alias，echo，printf

    126通常代表因为权限问题或者是命令无法执行。

    127命令未找到。要么PATH有问题，要么打错了

    128无效参数（exit命令接收一个正整数作为参数，负数、小数，非数值类型是不允许的

    致命错误 n：128+n

    在Linux中， 程序可以发送33种信号。当程序接收到这些信号并被终止时，它会发送一个错误码，等于128+信号的值

    例如，被ctrl C中止的程序，会收到SIGINT，值为2，所以返回值是128+2=130

    返回值为255，意为返回值超出0-255的范围

    在255以上的情况会导致错误的结果，因为wrapped around

    bash -c "exit 383"
echo $?
127

    Job control

    unix的process，process group，session是三个概念

    登陆shell是session和process group的leader。

    shell对它启动的每一个job，都会在当前的session创建一个process group。例如 ls ｜ head 是一个两个进程的pipeline，shell认为这是一个job，属于一个新的，单独的process group。

    shell有fore ground jobs和background jobs之分，前台的jobs是由终端控制的进程组，后台的jobs是未由终端控制的进程组。每个终端只有一个前台进程组。把一个job设为前台时，shell把它设置为前台进程组。把jobs转为后台时，shell把其他进程组或者shell自己设为前台进程组。前台的进程组可以从shell读写内容，Otherwise they receive SIGTTIN and SIGTTOU signals on attempts to read from and write to the terminal respectively. By default these signals suspend the process, although most shells mask SIGTTOU so that a background job can write to the terminal uninterrupted.

    #!/usr/bin/env python
import signal, time

def handler(signum, time):
    print("\n got a SIGINT, but I am not stopping")

signal.signal(signal.SIGINT, handler)
i=0
while True:
    time.sleep(.1)
    print("\r{}".format(i), end="")
    i += 1
